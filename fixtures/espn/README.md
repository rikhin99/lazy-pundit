# Scrubbed ESPN fixtures

Generated by `npm run scrub:espn` from the private raw fixtures. Don't edit them by hand: the script wipes and rewrites each folder.

Each folder is a snapshot folder, as in `fixtures/sleeper/`: `blobs/` holds the gzip payloads named by SHA-256, each `<snapshot id>/manifest.json` lists the requests of one fetch, and `weeks.json` maps each ranking week to its snapshot. Each request asks for a set of ESPN views, named in its URL; a week's box scores add `scoringPeriodId`.

## How the weeks are replayed

Each snapshot replays the season as of its week N, fetched the Tuesday after it with week N already scored:
- ESPN's current week is N, and only weeks 1 to N have box scores.
- Later regular-season matchups are listed unplayed: no winner, no points, no lineups. A playoff round is listed once the round before it is played.
- Each team's record (overall, home, away, division), points for and seed are rebuilt from weeks 1 to N. Seeds go by record, then points for, as ESPN's own did. Once the regular season is over, records and seeds are ESPN's own, and the final ranks appear only once the season is over.
- A week's box scores hold the teams' records as they stood that week, so the payload is the same in every snapshot that holds it.

Each team's acquisitions by week, and the league's transaction period, stop at week N. Current rosters, injuries, season transaction counts and season stat totals are as they were at the end of the season.

Neither set holds any transactions. The raw 2025 pulls asked for them once, after the season, and ESPN answers that request with the current week's transactions only, so they came back empty. The teams' acquisition counts show there were real adds and drops.

The snapshot IDs end with a hash of the payloads until the ESPN normalizer gives a data hash (#63 part b), so they will change then.

## Trimmed

Two things are too large to commit:
- **Projected stat lines** (`statSourceId: 1`) are gone everywhere except week 1's box scores, which every snapshot holds and which keep their lineups' projections for that week. That leaves projections in place for the normalizer to filter out.
- **Every matchup's per-stat breakdown** (`scoreByStat`) is emptied. Only category leagues use it.

Members' names and IDs, team names, abbreviations and logos, and the league IDs are deterministic fakes. The leagues' names are kept. Scores, lineups, players and their stats are real.
