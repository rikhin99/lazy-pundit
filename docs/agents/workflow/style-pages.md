# A change to a style page

Read when a ticket changes `style-pages.ts` (`ticket-workflow.md`, step 2).

Before launching the reviews, make a workspace in a scratch script with `eval "$(npm run -s fixture:workspace -- 10)"`, which enters it with week 10's replay and the clipboard off, so nothing is fetched. Publish there (`echo p | node <repo>/src/cli.ts publish`), and pass both pages to `npm run -s screenshot` (`find "$PWD" -name 'week-10.*.html' -exec npm --prefix <repo> run -s screenshot -- --label no-llm {} +`, since zsh passes a `$(…)` list as one argument). In #115 a scratch run in a fixture workspace without the replay sent a live request to Sleeper. Do it with no LLM, then again with an edited intro (a correction line included) and blurbs, labelled `edited`: in #120 an unlabelled second run overwrote the first's PNGs. Check that nothing overflows, overlaps, wraps badly or repeats, and give the reviews the PNG paths. Headless Chrome won't lay out narrower than 500px, so the script frames each page at 390px: in #59 part (b), screenshots of the page itself were cropped and looked like overflow, and the banner's stripe running under the heading was caught only by the spec review.
