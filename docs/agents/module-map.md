# Module map

Read this before opening source files. It says which file owns what. Within a file, `npm run outline -- <file>…` lists each exported declaration's line range and doc line (`--all` adds the internal ones; a test file lists everything): read the ranges you need with `sed -n`, and open a whole file only when you'll rewrite most of it. Line counts are rough sizes.

## The pipeline

`draft`: lore (`lore.ts`: a `{local}` stops here, its warnings go out through `onWarnings` before any call, and a clash of nicknames stops after the fetch) → `league.md` (`league-file.ts`: a malformed file or a `{local}` stops here, before the fetch, and its body's warnings go out) → the pundit settings (`pundit-settings.ts`) → fetch (`sleeper/fetcher.ts`; a failed one continues from the last complete snapshot, `refresh.ts` `fetchOrContinue`) → snapshot on disk (`snapshot.ts`) → League model (`sleeper/normalizer.ts`) → the starting order (`power-score.ts`) → stats and evidence (`draft-data.ts`, with the stakes' evidence and triggers from `stakes.ts`, whose warnings go out here, with the changed-outcome and Log-edit warnings against the newest frozen copy through the week, as `check` has them, `leagueFileChangeWarnings`) → the persona (`persona.ts`, capped by `league-file.ts`'s family league) → with an Anthropic key, the draft context (`draft-context.ts`, with last week's published blurbs read in `draft.ts`), the prompt (`prompt.ts`) and the LLM gate (`llm-gate.ts`: one call, then up to 2 retries for failing sections), each call through `llm-call.ts` (price and spend-cap check, LLM transcript, spend) → Markdown (`ranking-file.ts` `renderDraft`), with the LLM prose file beside it when the LLM wrote any section (`llm-prose-file.ts`; otherwise any earlier one is removed) → `checkDraft`.

`check`, `publish` and `refresh` all start from `checkDraft` in `check.ts`: read the latest `week-NN.md`, parse it, refuse front matter that `publish` and `refresh` couldn't edit (indented keys or a `{...}` flow map, `refuseUneditableFrontMatter`), rebuild the evidence from its snapshot, with its drastic corrections against the last published ranking's snapshot (`corrections.ts`; one that can't be read gives the can't-compare item), measure order evidence against the movement baseline (`movement.ts`), read the lore (`lore.ts`), warn of a changed outcome or Log entry against the newest frozen copy through the draft's week (`lastPublishedMeta`; one that can't be read gives none), validate each blurb, list moved teams, return the problems list and write any auto-tags (`refresh` asks it not to). `publish` then fetches in memory for the data-changed warning (a failed fetch is only a note), freezes the checked text with its edition, the Log entries through its week (`logRecord`) and the house rules' outcomes when they changed since the draft, and renders plain text with movement.

`refresh`: the pundit settings (`pundit-settings.ts`) → fetch in memory (`refresh.ts` `fetchOrContinue`, a routine fetch unless `--full`; a failed one continues from the last complete snapshot with the failed-fetch item, leaving `checked_at`; with none, it stops with the fix for what failed) → `diff` against the draft's snapshot (`data-diff.ts`, through the in-progress week a draft let in), with the newest scored week when it's later than the draft's → no change, `checked_at` only, plus `starting_order` and `power_score` if the settings ask for another method or weights than the draft recorded; a change, write the snapshot (which applies retention, `retention.ts`) and set the front matter's values (`setFrontMatterValue`), adding the old snapshot to `earlier_snapshots` → `checkDraft`, which reads those snapshots' evidence so a claim stays stale rather than wrong.

## Tests (`test/`)

The seams, and the helpers each one uses:

- **Library API against a temp workspace**, with `lore.md` at the workspace's root, `persona.md` at `pundits/rikhin/persona.md` and the family league in `seasons/2025/league.md` when a test writes them. Grep a test file's or helper's name for its line.
  - Test files: `draft-publish`, `style-pages` (reads the written page's text and its awards box or award chips), `refresh`, `corrections`, `movement`, `playoff-status`, `llm-draft`, `llm-fallback`, `persona`, `lore`, `check`, `config`, `doctor`, `init`.
  - `stats-table`: `statsTable` after drafting week 10 (or week 7 with the in-progress week 8, or week 0), with the pundit's moves and broken drafts written over the file; `renderStatsTable` and `statsTableLook` on a literal table, since the CLI test's output is never a terminal.
  - `stats-view`: `renderStatsView` and `statsViewStep` on a literal table; `statsView`'s endings (a signal by `process.emit`, a drawing error by an output whose `write` throws) on a fake terminal over a drafted Fear The Turtle workspace. The terminal itself (the alternate screen, keys, exit codes, SIGTERM and SIGHUP, a closed tab, a resize, `--sort` and refusals opening no screen) is `npm run -s drive:table -- all` (`scripts/drive-table.exp`, about 10s), which CI runs after the wizard's; each scenario waits for the footer of each screen before its next key.
  - `preview`: `startPreview` on a drafted week 10 from a free port, the page read with `fetch` and picked apart by its markup (`panel`, `tab`, `plainText`, `framed`), the reload channel read by `reloads`, and the deps' transport recording every request.
  - `demand-test`: `stats` after drafting, editing and publishing weeks at chosen clocks, with `scriptedLlm` for an LLM week.
  - `retention`: snapshots nothing names, written with `fetchSleeperSnapshot` into the workspace's folder at a chosen clock.
  - `stakes`: `league.md` written beside the draft; a patched fetch for ties and drastic corrections.
  - `init-steps`: steps 3 to 7, the checklist and init then draft.
  - `rerun`: `setup <step>` with a recording confirm.
  - `in-progress`: drafting mid-week and `--include-in-progress`, on week 8 patched to `last_scored_leg: 7`.
  - `init-espn`: the league data step on ESPN (`checkEspnLeague`, public and private leagues, a rejected cookie and a wrong league ID), the cookie saved by `setUpWorkspace`, and `setup espn`.
  - `hotTakeryAt(deps, week, { status, privateTo, league })` in `support/espn.ts` gives the deps replaying Hot Takery's committed ESPN snapshot: `status` answers the league request (`HOT_TAKERY_LEAGUE_URL`) with it, `privateTo` answers 401 to any request without that cookie, and `league` patches the league payload (the standings stay, rebuilt from the matchups). `correction: { week, points }` is the ESPN data change for a `refresh` run: that week's first home box score `points` higher.

  - `fearTheTurtle(week)` in `support/workspace.ts` gives a workspace, deps that replay the committed snapshot, a recording clipboard and a fixed clock.
  - `onStandings(week)` is the same with the pundit settings on the standings method, for literals that follow a team's place.
  - `rankingsDir(dir)` finds the files.
  - `atWeek(deps, week)` replays a later week, to publish one week and draft the next in the same workspace.
  - `preseason(deps, patch?)` makes week 1's replay a preseason (no scored week, every roster's record and points zeroed, then `patch`'s league and roster changes); `preseasonReplay(patch?)` writes it as a snapshot and gives the folder for the CLI's `LAZY_PUNDIT_REPLAY`.
  - `published(dir, deps)` publishes and fails the test if it's held back.
  - `twoTeamLore()` gives a workspace at week 8 whose `lore.md` is the lore step's own for two teams with linked handles, and `writeBody(body)` to write its sections by hand under the step's top.
  - `failingOn(deps, url, { params, answer })` fails the fetch on one request: the one for `url` with each of `params` (a week's ESPN box scores or transactions share one URL, told apart by `scoringPeriodId`), answered with `answer` (a status and body), or rejected as offline.

  - `withoutReminder(problems)` drops the correction-timing reminder every draft of a scored week carries, so a clean list reads `[]`.
  - `frontMatter(text)` parses a file's front matter.

- **LLM client** (`anthropic-llm`): `anthropicLlm` against a transport that records requests and answers with a canned Messages API body.
- **Validator** (`validator`): `blurb()` and `week8Evidence()` in `support/week8-evidence.ts` hold literal week-8 evidence, with `week8Nicknames()`, `week8Order()`, `id(n)` for a team ID and `corrected(team, delta)` for the pack after a score correction; `support/plain-prose.ts` lists sentences that must never come back hard (`PLAIN_PROSE`), true tagged claims that must never come back hard (`TAGGED_PLAIN`: extend it when a rule judges the words inside a tag), true untagged claims naming several teams, each with its section and the IDs they must verify against (`TRUE_UNTAGGED`: extend it when a change moves which team or week a claim reads) and claim-heavy blurbs (`CLAIM_HEAVY`). An untagged claim gets an `id` when verified; a wrong one has no `id`, only its `reason`. Writing a test sentence for a number cue: a cue after the number counts only within 25 characters and only when none comes before it, and a digit inside a cue ("last 3") is a claim of its own. `npm run -s claims:diff [-- <ref>]` (`scripts/claims-diff.ts`) prints each of these sentences, and the cue-pair sentences in `scripts/claims-diff-report.ts` (`CUE_PAIRS`), whose claims read differently in the working tree than at the ref; `test/claims-diff-report.test.ts` tests the comparison with stub validators.
- **Fetcher** (`fetch-sleeper`): the committed replay through `patchingTransport(fileTransport(FIXTURES, WEEKS[n]), …)`, patching the league payload's `settings` to set the current and scored weeks (`support/workspace.ts`: `FIXTURES` is the replay folder, `WEEKS` maps a ranking week to its committed snapshot ID (weeks 1, 7, 8, 9, 10, 14, 15 and 17; in week 15 `sleeper:3` and `sleeper:11` have byes, so a week-15 evidence pack holds their week-14 weekly stats, and in week 17 `sleeper:1`, `:2`, `:5` and `:8` do, the only cases of an earlier week in a pack; week 17 holds every playoff game, and before the playoffs the brackets are projected, so `losersBracket` is true in every week), and `statCorrection(rosterId, points)` patches a matchups payload). A patch can also be `{ replaceWith }`, a whole new answer, such as the `null` Sleeper answers for a league it doesn't know. The snapshot and players-file cases replay week 8 through the file's `replay()`, which also records requests and fails one URL with a 500.
- **ESPN normalizer** (`espn-normalizer`): `snapshotOf(dir, week)` reads a committed ESPN snapshot, and `patched(snapshot, url, patch, params?)` changes one payload of it in memory (a week's box scores or transactions take `scoringPeriodId`), and `withLaterRounds(snapshot, games)` adds winners-bracket weeks after week 15 to the schedule and box scores (each side its team's week-15 side), for round 2 and the final; `espn-pipeline` runs `draft` then `publish` on the Hot Takery set, and the rejected-cookie fix lines through `refresh` and `draft`.
- **League model and stats** (`sleeper-normalizer`, `standings`, `playoff-status`, `stats`, `data-hash`, `data-diff`, `power-score`, which also holds the settings' library-API cases): `committed(week)` and `patched(week, patches)` in `support/workspace.ts`.

- **ESPN fetcher** (`fetch-espn`): replays a committed ESPN set (`fixtures/espn/hot-takery-2025`, weeks 1, 7, 8, 9, 10, 14 and 15; `family-league-2025`, weeks 14 and 15, team IDs with gaps and two week-15 byes) through `fileTransport`, with the file's own `replay(week, { set, status, league, schedule })` answering the league request with a status, or patching the league or schedule payload through `patchingTransport` (a week's box scores or transactions share one URL, so patch those by hand).
