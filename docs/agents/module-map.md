# Module map

Read this before opening source files. It says which file owns what. Within a file, `npm run outline -- <file>…` lists each exported declaration's line range and doc line (`--all` adds the internal ones; a test file lists everything): read the ranges you need with `sed -n`, and open a whole file only when you'll rewrite most of it. Line counts are rough sizes.

## The pipeline

`draft`: lore (`lore.ts`: a `{local}` stops here, its warnings go out through `onWarnings` before any call, and a clash of nicknames stops after the fetch) → `league.md` (`league-file.ts`: a malformed file or a `{local}` stops here, before the fetch, and its body's warnings go out) → the pundit settings (`pundit-settings.ts`) → fetch (`sleeper/fetcher.ts`) → snapshot on disk (`snapshot.ts`) → League model (`sleeper/normalizer.ts`) → the starting order (`power-score.ts`) → stats and evidence (`draft-data.ts`, with the stakes' evidence and triggers from `stakes.ts`, whose warnings go out here, with a changed outcome's against the last published ranking's `house_rule_outcomes`) → the persona (`persona.ts`, capped by `league-file.ts`'s family league) → with an Anthropic key, the draft context (`draft-context.ts`, with last week's published blurbs read in `draft.ts`), the prompt (`prompt.ts`) and the LLM gate (`llm-gate.ts`: one call, then up to 2 retries for failing sections), each call through `llm-call.ts` (price and spend-cap check, LLM transcript, spend) → Markdown (`ranking-file.ts` `renderDraft`) → `checkDraft`.

`check`, `publish` and `refresh` all start from `checkDraft` in `check.ts`: read the latest `week-NN.md`, parse it, rebuild the evidence from its snapshot, measure order evidence against the movement baseline (`movement.ts`), read the lore (`lore.ts`), validate each blurb, list moved teams, return the problems list and write any auto-tags (`refresh` asks it not to). `publish` then fetches in memory for the data-changed warning (a failed fetch is only a note), freezes the checked text with its edition and renders plain text with movement.

`refresh`: the pundit settings (`pundit-settings.ts`) → fetch in memory (`refresh.ts` `fetchFresh`) → `diff` against the draft's snapshot (`data-diff.ts`) → no change, `checked_at` only, plus `starting_order` and `power_score` if the settings ask for another method or weights than the draft recorded; a change, write the snapshot and set the front matter's values (`setFrontMatterValue`), adding the old snapshot to `earlier_snapshots` → `checkDraft`, which reads those snapshots' evidence so a claim stays stale rather than wrong.

## Tests (`test/`)

The seams, and the helpers each one uses:

- **Library API against a temp workspace** (`draft-publish`, `refresh`, `movement`, `playoff-status`, `llm-draft`, `llm-fallback`, `persona`, `lore`, `stakes` (`league.md` written beside the draft; a patched fetch for ties and drastic corrections), `check`, `config`, `doctor`, `init`, `init-steps`: steps 3 to 7, the checklist and init then draft), with `lore.md` at the workspace's root, `persona.md` at `pundits/rikhin/persona.md` and the family league in `seasons/2025/league.md` when a test writes them: `fearTheTurtle(week)` in `support/workspace.ts` gives a workspace, deps that replay the committed snapshot, a recording clipboard and a fixed clock; `onStandings(week)` is the same with the pundit settings on the standings method, for literals that follow a team's place; `rankingsDir(dir)` finds the files; `atWeek(deps, week)` replays a later week, to publish one week and draft the next in the same workspace; `published(dir, deps)` publishes and fails the test if it's held back; `frontMatter(text)` parses a file's front matter. `operator()` gives deps alone, with temp config, cache and workspaces folders and no environment overrides and `noLlm`, so nothing touches the real home directory or calls an LLM. For LLM drafts, set `deps.llm = scriptedLlm(...)` (`support/llm.ts`, which records each request; a scripted answer can be text, a reply with token counts, or an `LlmError` to throw) and `deps.env.anthropicApiKey`.
- **LLM client** (`anthropic-llm`): `anthropicLlm` against a transport that records requests and answers with a canned Messages API body.
- **Validator** (`validator`): `blurb()` and `week8Evidence()` in `support/week8-evidence.ts` hold literal week-8 evidence; `support/plain-prose.ts` lists sentences that must never come back hard.
- **League model and stats** (`sleeper-normalizer`, `standings`, `playoff-status`, `stats`, `data-hash`, `data-diff`, `power-score`, which also holds the settings' library-API cases): `committed(week)` and `patched(week, patches)` in `support/workspace.ts`.
- **CLI** (`cli`): spawns `src/cli.ts` in a workspace with `LAZY_PUNDIT_CLIPBOARD=off`, `LAZY_PUNDIT_REPLAY` on the week-8 snapshot so a fetch stays offline, and HOME and the XDG folders in a temp home; `homeListing()` writes a `config.yaml` for `--league`.
- **Repo rules** (`injected-boundaries`, `format-versions`, `glossary-terms`, `sleeper-fixtures`).
- **Direct imports**: a test may import from a `src/` module what `index.ts` doesn't export, when the case can't be set up through the library API. `draft-publish` does this for `setFrontMatterKey`, on front matter that `publish` refuses first.

Fixture values for hand-checked literals: `npm run fixture:show -- <week> --model`. A workspace with a draft for running the CLI by hand: `npm run fixture:workspace`. The `init` wizard through a real terminal, in a temp home and offline: `npm run -s drive:wizard -- <scenario>`, with the scenarios at the top of `scripts/drive-wizard.exp`; it needs `expect`, so it isn't in CI.
